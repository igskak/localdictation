# Задание для отдельного треда: Witness для Windows

Скопировать текст ниже в новый тред, открытый в этом репозитории и имеющий доступ к актуальному рабочему дереву.

---

Реализуй Windows-версию Witness по `docs/WINDOWS_IMPLEMENTATION_PLAN.md`, последовательно пройдя W0–W8 до устанавливаемой закрытой беты, которую я затем передам реальным тестировщикам. Сейчас прошу именно реализацию, а не новый обзор или только прототип.

У меня Mac, нет Windows-компьютера, я не хочу устанавливать Windows или локальную виртуальную машину. Используй Windows CI для сборки и доступных автоматических проверок, а pure Core tests запускай также локально. Реальные микрофоны, Windows 11, видеокарты и совместимость приложений будут проверены внешними тестировщиками после получения беты. Не заказывай тестирование и не пиши исполнителям.

Сначала прочитай корневой `AGENTS.md`, план целиком и исходники последнего опубликованного Mac-релиза. Подтверждённая 2026-09-27 основа — **Witness 0.6.8/build 9**, tag `v0.6.8`, commit `c073a8fbad5fe1cca7ef6dcf06fc7c19c2c89b77`, опубликованный 2026-09-24. Локальное рабочее дерево на `f66081e59839c8af6bcfcddec64c8992fb0ad391` с незакоммиченной версией 0.6.2/build 3 отстаёт: не принимай его за актуальную продуктовую спецификацию. Release commit уже доступен через `git show <commit>:<path>`, даже если тег отсутствует локально. Проверь latest release/tag commit заново; если вышло обновление, сначала сверяй его изменения. Новые локальные правки сравнивай отдельно, не откатывая функции опубликованного релиза. Не сбрасывай и не включай чужие правки в свои коммиты.

Базовая архитектура: отдельная папка `Windows/`, C#/.NET 10/WPF, тестируемое Core без Windows-зависимостей, стандартные Win32/WASAPI/Media Foundation adapters, in-process whisper.cpp через небольшой native C ABI, CPU fallback и опциональный Vulkan. Уточни область Mac-specific правил в AGENTS.md для нового Windows-target, не ослабляя общие продуктовые ограничения. Не переписывай существующий Mac-клиент.

Обязательно сохрани актуальные возможности:

- Hold-to-talk и toggle, изменяемый shortcut, startup, выбор микрофона с fallback и сохранением уже записанной фразы при отключении.
- Языки из каталога движка, ограничение выбранным набором, session language pin и continuity; progress/retry загрузки модели.
- Правила 0.6.7/0.6.8: финальный язык по завершённой записи, без решения по первым 1.5 секундам. Leading-silence regression corpus с паузами 0.5/1.0/1.5/2.5 s обязателен. Исследуй устранение повторного encoder pass внутри одной диктовки в whisper.cpp; включай reuse только с доказанной on/off parity, без сохранения tensors между записями. Core ML-класс не переносится буквально; если API не позволяет безопасную оптимизацию, сохрани корректность и явно зафиксируй performance gap.
- Осторожная очистка, risk signals, два review-порога, нулевой вес confidence до измерений, raw text/replay, необязательная проверка после вставки.
- Безопасная вставка, отсутствие двойного paste/старой диктовки, protected-field refusal, сохранность нового clipboard, no-focus recording/processing badge.
- Последние 10 текстов только в RAM, раскрываемая история с видимым viewport и прокруткой, декоративные overlays без перехвата кликов; settings/glossary/license persistence, EN/DE интерфейс и все текущие разделы Settings.
- Три дня без email от первого непустого результата, десять дней trial от server activation, LD1/Ed25519, annual/lifetime, device release и тот же wire contract. Не копируй устаревшие 5 диктовок/14 дней из старых документов.
- Ручные подписанные обновления: check только по кнопке, download/install после подтверждения, без auto-apply при следующем запуске, проверка подписанного manifest и точного пакета, сохранность данных A→B, ограничение major по lifetime.
- Local-first, никаких audio/transcript/vocabulary/clipboard/application contents или производных от них в сети, файлах логов либо CI artifacts. Аудио только в памяти. Три разрешённых продуктовых события — по существующей политике; beta local-only. Запрет Windows Cloud Clipboard/history для каждого копирования текста Witness.

Не считать экспериментальные word timestamps или доступность системного словаря доказанными: проверь выбранный движок, явно обрабатывай segment fallback и отсутствующий lexicon. Учти различие Swift Character / C# UTF-16 / native UTF-8.

В `Service/` релиза 0.6.8 уже есть отдельные server-side события в PostHog EU (`trial_issued`, `license_purchased`, `license_renewed`, `license_refunded`) и соответствующие privacy disclosure/tests; локальная старая копия их не содержит. Не откатывай сервер к ней и не дублируй эти события в Windows-клиенте. Beta transport/authority изолированы от production, включая серверные события.

Для installer/updater проверь Velopack и verified update-source spike в W0; не откладывай выяснение signature/installation API до конца. Для Ed25519 используй проверенную библиотеку, не свою криптографию. Все зависимости закрепляй и документируй их лицензии и необходимость до добавления. Mac Sparkle feed использует GitHub releases/latest: Windows-релизы не должны его сломать.

Подготовь и используй Windows CI, если доступ к нему уже есть. Не объявляй сборку проверенной, пока нет реально выполненного run. Если для запуска нужен недоступный remote/access, назови точную проблему и продолжи независимую реализацию и локальные проверки. Не запрашивай установку VM. Не выдавай Windows Server/admin CI, mock adapters или synthetic speech за проверку Windows 11, физических микрофонов и реальной точности.

Работай законченными срезами с тестами по плану. Веди `Windows/IMPLEMENTATION_STATUS.md`: completed/pending, выполненные команды и CI runs, известные ограничения и следующий шаг. Если работа переносится между сообщениями, этот файл должен позволять продолжить её без повторного исследования. Обычные технические решения принимай самостоятельно в рамках плана. При отсутствии внешних credentials продолжай все не зависящие от них части.

Production purchases, серверный deploy, изменение публичных условий, публикация release и отправка сообщений тестировщикам в это задание не входят. Подготовь их конфигурации/документы, но не включай Mac-only checkout в Windows beta. Beta license/update authorities должны быть отделены от production; private keys и реальные пользовательские данные не коммить.

Результат: Windows beta installer и SHA-256, реализованный и проверенный update A→B, отчёт CI/tests, licenses/notices, `TESTER_GUIDE.md`, `QA_CHECKLIST.md`, `BUG_REPORT_TEMPLATE.md`, `KNOWN_ISSUES.md` и актуальный status. Отдельно укажи, что осталось проверить на реальных ПК и какие signing/feed credentials нужны для внешней раздачи. Если обязательная часть ещё не готова, не называй весь перенос завершённым.
